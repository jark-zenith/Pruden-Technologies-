# PTMS Financial Intelligence — Integration Setup

## Current deployment target
- Backend service: `pruden-command-secure`
- Render region: Frankfurt
- Repository: `jark-zenith/Pruden-Technologies-`
- Backend URL: `https://pruden-command-secure.onrender.com`
- Frontend static site: `pruden-technologies` (separate Render service)

## Safety defaults
Daraja and project payment webhooks must remain disabled until credentials, callback URLs, and account ownership are configured. Do not place credentials in Git, frontend Vite variables, chat messages, or client-side storage.

## Render environment variables
Set the following on the **backend web service only**. Empty secret values should remain unset until Safaricom onboarding is complete.

## Safaricom setup later
1. Create/select the Daraja app in the Safaricom developer portal.
2. Use sandbox credentials first; do not use production credentials in sandbox.
3. Configure the registered shortcode and passkey appropriate to the selected API.
4. Register the callback endpoints generated by the deployed PTMS backend.
5. Run sandbox STK Push, C2B and status tests with test data only.
6. Confirm callback delivery, idempotency, reconciliation, and audit records.
7. Keep B2C/B2B disabled until a separate payment approval and recipient verification test passes.

## Personal M-Pesa wallet limitation
Daraja does not grant universal access to all transactions on a personal phone-number wallet. Personal wallet records must initially be imported from an authorized statement export unless Safaricom offers an approved API for the account type.

## Data model
The migration adds multi-account support, normalized transactions, double-entry ledger lines, budgets, integration-event receipts, and optional account/project references on the legacy finance table. Existing legacy rows remain intact.
